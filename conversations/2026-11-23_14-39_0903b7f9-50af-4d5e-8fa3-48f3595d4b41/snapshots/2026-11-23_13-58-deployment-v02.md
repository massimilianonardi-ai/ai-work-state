# Deployment manager — requirements refinement (2026-11-23)

Conversation: 2026-11-23_14-39_0903b7f9-50af-4d5e-8fa3-48f3595d4b41; branch 0; checkpoint 2.

## User-set requirements
- POSIX shell program launches interactive menu with zero arguments, conventional CLI with arguments.
- Owns and maintains a single `deployment.json` describing the complete deployment across multiple servers.
- Can read/view the infrastructure and make granular mutations to selected resources, e.g. add application, change app authorization, rotate secrets.
- Installs/manages components through both m-os and native host mechanisms: APISIX, nginx, OpenResty, PostgreSQL, Podman and others.
- Manages service processes and settings: environment, start commands, run-as users, dependencies, lifecycle.
- Manages product resources Keycloak, APISIX, PostgreSQL, GeoServer and networking: realms, clients, users, roles, permissions, apps, services, paths/URLs, DB/schema, WMS/WFS, IP, port, DNS, certs.

## Investigated interfaces
- Verified `massimilianonardi-ai/m-os` README and `res/sys/manual/srv` on master: `m pkg`, provider/facility-based `srv start/stop`, `srv host user|system install/start/stop/restart`. `srv` is not a generic arbitrary-command service definition mechanism; native backend and/or future extension required for other service types.
- Verified official product Admin/REST docs for Keycloak, APISIX and GeoServer; PostgreSQL uses SQL and system/native administration. Feature coverage needs adapter capability tests per version.

## Proposed design, not yet approved
- Unified command dispatcher for CLI and menu; no duplicated business logic.
- `deployment.json` versioned normalized resource graph with stable resource identities, host/resource links, ownership and dependencies; distinguish desired/spec from observed/status including provenance/time; never silently infer live read success.
- Targeted updates: read -> validate -> calculate dependency impact -> preview -> confirm side effects -> atomically update file and reconcile only affected resources -> verify; failures recorded with partial outcome.
- One central JSON, secret references only (no cleartext credentials); protect access, redaction and audit; no auto destructive pruning or arbitrary eval of JSON.
- Remote transport proposed agentless SSH and product-native APIs; utilize m-os srv where its contract applies, otherwise native supervisor. Administrative privilege model must be explicitly verified.
- No product code changed and no deployment executed.

## Open decisions / acceptance gates
- Confirm desired-vs-observed representation in same JSON, external drift behavior, secret backend strategy, remote privileges/platform targets, support scope for externally managed DNS/TLS.
- Next: formal JSON schema, resource ownership contract, CLI grammar, target adapter matrix and acceptance cases; present a complete synthesis before implementation.
