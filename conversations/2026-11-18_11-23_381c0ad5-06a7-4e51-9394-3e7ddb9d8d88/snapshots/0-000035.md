# AI-Workflow — independent cross-chat review concept

Source: user's proposal during the rsudo Keycloak real-world test, 2026-11-23. Candidate design, not yet an approved protocol change.

Goal: while conversation A performs design/development, conversation B independently audits efficiency, requirement fidelity, technical grounding and real progress, using verified persisted state; operator provides approved corrective feedback to A.

Available today: conversation A's branch checkpoints, six meaningful events, eight snapshots, and m-rsudo repository commits and build CI. The Keycloak conversation branch currently has tasks: [] and no canonical Keycloak task record. This permits partial technical review but weakens independent reconstruction of accepted scope and approvals.

Minimum sources for credible review: current approved product contract/constraints and provenance; significant state changes and decision rationale; current phase, accomplishments and blockers; links to code revisions, tests and observed results; reviewed chat-id/branch-id/message-id and Git SHA. Record such information at meaningful changes and handoffs, not through repetitive per-turn metadata.

Limit: events/snapshots and self-reported summaries cannot establish how many repetitive questions or digressions occurred; evaluating interactive conduct requires actual message excerpts, a trusted transcript, or other direct evidence. Lack of transcript must be declared.

Safety/authority: reviewer reads target context without changing it, produces evidenced findings and recommendations; operator decides whether to relay/apply feedback. Reviewer must not silently modify the active work, product code, or accepted requirements. Findings are anchored to the target's exact verified checkpoint to avoid stale criticism.
